# Design Note — Issues #1411, #1412, #1413, #1414

## Overview

This document describes the design decisions for four coordinated features
delivered in a single wave.  Each feature is a bounded vertical slice spanning
backend services, route handlers, and frontend UI components.

---

## #1411 — Responsible game limits for aggregate active stake

### Ownership
`ActiveStakeLimitsService` (`backend/src/services/activeStakeLimitsService.ts`)
owns the single, authoritative enforcement gate.

### State transitions
A player's active stake is the sum of `stake` values from `playerChoices` JSONB
across all rounds whose state is `OPEN` or `CLOSED`.  Both states are included
because a `CLOSED` round may roll back to `OPEN` on transient failure.

### Failure behaviour
If the PostgreSQL query fails the check is treated as **blocked** (safe default)
to prevent a partial DB failure from becoming a bypass vector.  The error is
logged and `ActiveStakeLimitError` is raised.  Callers surface this as HTTP 409.

### Compatibility
- No existing REST surface changes.
- `POST /api/arenas` now calls `assertBelowActiveStakeLimit` before recording
  the join.
- `GET /api/users/me/stake-limit` is a new read-only endpoint for the frontend.
- `JoinArenaModal` fetches the limit on open and disables the confirm button if
  the join would breach it.  The server-side check is the authoritative gate;
  the frontend check is a UX convenience.

### Configuration
`MAX_ACTIVE_STAKE_USDC` (env `MAX_ACTIVE_STAKE_USDC`, default 10 000).

## #1412 — Arena health summary combining chain lag, queue lag, and state drift

### Ownership
`ArenaHealthService` (`backend/src/services/arenaHealthService.ts`) evaluates
and publishes the composite health status.

### Signals
| Signal | Source | Warn | Critical |
|---|---|---|---|
| `chainLag` | Age of last RESOLVED/SETTLED round | 120 s | 300 s |
| `queueLag` | Age of oldest PENDING transaction | 60 s | 180 s |
| `stateDrift` | Time beyond expected round-state TTL | 90 s | 240 s |

Health transitions are derived exclusively from these explicit thresholds.
Each signal includes an `evidenceAt` ISO timestamp for log correlation.

### Compatibility
New endpoint: `GET /api/arenas/:id/health` (10 s cache).
No existing endpoints change.

### Frontend
`ArenaHealthBadge` component (`frontend/src/components/arena/ArenaHealthBadge.tsx`)
polls the health endpoint every 15 s and renders a compact or full status view.
Status changes are announced via `aria-live="polite"`.

## #1413 — Winner claim fee sponsorship eligibility workflow

### Ownership
`FeeSponsorshipService` (`backend/src/services/feeSponsorshipService.ts`) owns
the full token lifecycle.

### State model
```
PENDING → CONSUMED  (terminal, irreversible)
PENDING → EXPIRED   (lazy, on TTL elapsed at consume time)
```

### Key invariants
- A token is **quoted once** (issued per `(payoutId, winnerId)` pair) and
  **cannot be reused** for another claim — enforced by the atomic
  `PENDING → CONSUMED` transition.
- Idempotency: issuing twice for the same pair returns the existing token.
- Expired tokens are detected lazily at consume time to avoid a background sweep.

### Compatibility
- New admin endpoints: `POST /api/payouts/eligibility`,
  `POST /api/payouts/eligibility/:tokenId/consume`,
  `GET /api/payouts/eligibility/:tokenId`,
  `GET /api/payouts/eligibility/winner/:winnerId`.
- Feature is gated by `PAYOUTS_FEE_SPONSORSHIP_ENABLED=true` (default false).
- `TransactionModal` accepts an optional `feeSponsorshipEligibility` prop and
  renders a badge when the token is `PENDING`.

### Configuration
- `PAYOUTS_FEE_SPONSORSHIP_ENABLED` — enable the feature.
- `PAYOUTS_FEE_SPONSORSHIP_TTL_HOURS` — token TTL (default 72 h).

## #1414 — Privacy-preserving public player aliases with rotation history

### Ownership
`AliasService` (`backend/src/services/aliasService.ts`) owns uniqueness,
profanity checking, and history.

### Privacy guarantee
Wallet addresses are **never** returned in any alias-related response.
Historical game results remain attributable via the alias slug, not the wallet.

### Uniqueness enforcement
- Case-insensitive uniqueness enforced across active aliases.
- A retired alias is locked for `ALIAS_GRACE_PERIOD_DAYS` (30 days) to prevent
  impersonation.

### Profanity filtering
A built-in block-list is included.  Operators may extend it via
`ALIAS_BLOCK_LIST` (comma-separated values in env).

### History
Alias history is stored in `aliasHistory[]` on the Mongo `User` document.
The array is capped at 50 entries per user to prevent unbounded growth.
History is returned newest-first from `GET /api/users/me/alias/history`.

### Compatibility
- New endpoints: `PUT /api/users/me/alias`, `GET /api/users/me/alias/history`,
  `GET /api/users/alias/:alias`.
- `displayName` on the `users.me` response is back-filled from the active alias.
- `UserModel` gains an `aliasHistory` field and a sparse case-insensitive index.
- `AliasManager` component on the profile dashboard provides edit/history UI
  without ever exposing the wallet address.
