# Cross-stack implementation plan (issues #1718, #1720, #1721, #1722)

This branch introduces only **pure frontend domain helpers and tests** for tournament advancement and minority-choice behavior. It does **not** implement the four complete features. Do not close the issues based on this branch.

## #1718: Three-option minority arenas
- Decide tie and zero-reveal semantics with protocol maintainers; the frontend helper currently ignores zero-vote choices.
- Add factory validation for option_count 2 or 3, versioned storage/serialization snapshots, Rust choice variant and matching TypeScript vectors.
- Update contract tally and resolution, event schema, proof verifier, live choice UI, and contract/integration tests.

## #1720: Arena-scoped session keys
- Design on-chain permission grant/revoke with arena, operation, player and expiry binding, replay protection, fee sponsorship and wallet revocation.
- Never store raw private keys in localStorage. Provide explicit opt-in and expiry, fallback wallet signing, and multi-device behavior.
- Integrate commit and auto-reveal only after contract authorization exists. Test expired and revoked grants.

## #1721: Multisig governance
- Persist typed proposals and immutable XDR/parameters, enforce signer identity and threshold from current Horizon state.
- Preview decoded actions and diffs, collect signatures securely, revalidate time bounds and signer sets before submission, and record chain confirmation and audit events.
- Reuse ops-cli mutation plans and add backend integration tests.

## #1722: Tournaments
- Add Prisma Tournament, TournamentStage, TournamentEntry models and migrations.
- Implement idempotent stage orchestrator, template-based arena creation, invites and whitelist, prize funding, cancellations and no-show transitions.
- Connect pure advancement rules to verified on-chain results; implement live bracket UI and tests for stage transitions.
