# Golden test vectors

Checked-in vectors that the **Rust** (`contract/arena`) and **TypeScript**
(`frontend`) test suites both assert. Any divergence between the two
implementations of commit-reveal hashing, metadata hashing, or amount
encoding fails CI on the side that drifts.

## Files

| File | Covers |
| --- | --- |
| `commitment.json` | `compute_commitment`, canonical metadata hashing, amount encoding |

## Spec

- **Commitment**: `SHA256([choice_byte] ++ salt_32_bytes)` with `Heads = 0`,
  `Tails = 1`. Matches `ArenaContract::compute_commitment`
  (`contract/arena/src/lib.rs`) and `computeCommitment`
  (`frontend/src/shared/lib/stellar/commit-reveal.ts`).
- **Metadata hash**: SHA-256 over the canonical JSON serialization
  (lexicographically sorted keys, no insignificant whitespace, arrays preserved,
  `undefined` omitted, `null` kept). Matches `metadata-hash.ts` and
  `backend/src/utils/metadataHash.ts`.
- **Amount encoding**: integer decimal strings map 1:1 onto `i128`; fractional
  and negative values are rejected by both sides.

Each commitment vector carries a `context` object (`arena` strkey, `round`,
`player` strkey) plus `arenaXdr` and `playerXdr`, the ScVal XDR bytes of each
address. The preimage is `"IA_COMMIT_V1" || arenaXdr || round_u32_be ||
playerXdr || choice_byte || salt` (#1630), so the hash is bound to one arena,
round, and player. Rust checks the hash from the XDR fields; TypeScript derives
the XDR from the strkeys and must agree.

## Consuming the vectors

- **Rust**: `cargo test -p arena commitment_vectors`
- **TypeScript**: `cd frontend && npx jest shared/lib/stellar/__tests__/test-vectors`

## Regenerating

The vectors are generated by the Rust test helper in
`contract/arena/src/commitment_vectors.rs`. To recompute and rewrite the file:

```bash
cd contract
BLESS_TEST_VECTORS=1 cargo test -p arena commitment_vectors -- --nocapture
```

`--bless` mode recomputes every hash from first principles (independent SHA-256,
not the in-contract helper) and overwrites `commitment.json`. Review the diff
carefully — a changed hash means an implementation changed on one side.

After blessing, run both suites to confirm agreement:

```bash
cd contract && cargo test -p arena commitment_vectors
cd frontend && npx jest shared/lib/stellar/__tests__/test-vectors
```

## Adding a vector

1. Add the case to `VECTORS` in `contract/arena/src/commitment_vectors.rs`.
2. Run `BLESS_TEST_VECTORS=1 cargo test -p arena commitment_vectors`.
3. Commit the updated `commitment.json` alongside the Rust change.
4. The Jest test picks the new vector up automatically — no TS change needed.
